# 0003 - MapLibre public map stack

Date: 2026-04-27

## Decision

Use MapLibre GL JS as the public app's map renderer.

Serve the MVP with precomputed route and stop GeoJSON generated by the TypeScript pipeline. Keep route geometry construction, spatial joins, clipping, simplification, hotspot scoring, and later tile generation outside the browser and outside the Worker request path.

Register the PMTiles protocol in the web app now so generated vector tile archives can later be served from R2 or static assets without replacing the map client. The initial map may still render simple GeoJSON layers over a raster basemap while route and hotspot artifacts are small.

## Why

The product is fundamentally a geospatial analysis interface, not just a static basemap with markers. MapLibre gives us a WebGL layer model for route lines, stops, labels, hover/click hit areas, and future corridor/hotspot overlays. It also gives us a migration path from GeoJSON to vector tiles or PMTiles when the map needs to show larger systemwide datasets.

Leaflet is adequate for the current route fixture, but it pushes more map behavior into imperative per-layer objects and DOM markers. That gets less useful as we add generated overlays, style expressions, route filtering, and precomputed artifact layers.

## Consequences

- `apps/web` owns only presentation-layer map rendering and interaction state.
- `packages/domain` should own shared GeoJSON/map artifact contracts when generated map data becomes a cross-package boundary.
- `tools/pipeline` remains responsible for heavy geospatial construction and artifact generation.
- R2 or static assets are the preferred home for generated GeoJSON, PMTiles, route briefs, and source snapshots.
- D1 or Postgres should store metadata, artifact indexes, route/month facts, and serving summaries, not large map payloads.
- The app should not depend on design-system CSS or scaffolding from the reference map-strategy repo; reuse only architecture and data-shape ideas that fit this codebase.

See `knowledge/wiki/engineering/map_strategy.md` for source IDs, generated artifact rules, and the implementation checklist.
